Model Distillation

Claude claude-opus-4-6 acts as the teacher, labelling ethical scenarios with structured JSON output. The Pragma model (Phi-3-mini LoRA adapter) learns to replicate this reasoning — at a fraction of the inference cost.

Feedback-Driven Training

Every thumbs up/down is stored by category and model version. collect_feedback.py identifies which categories have approval below 70% and auto-generates more targeted training examples for those areas.

Provider Phase-Out Plan

Claude and OpenAI are offline teachers only — used to bootstrap training data, not as the long-term production path. As the Pragma model matures, third-party LLM dependency drops to zero.

L1 Compliance Engine

Deterministic, synchronous rule evaluation — no LLM call, no latency. Catches most violations before reaching L2.

HOLC Geo Redlining

500+ historically redlined zip codes across 35 US cities, loaded from geo_data.py at startup. Any decision where context.zip_code maps to a redlined area is flagged as a potential Fair Housing Act violation.

ECOA Proxy Variables

35+ proxy fields detected: zip_code, last_name, ip_country, email_domain, neighborhood descriptors, national origin indicators. Compound risk detection when multiple proxies appear together.

Text Scanner — 14 Patterns

Indirect discriminatory phrasing: "that part of town", "near retirement", "family obligations", "mother tongue", "criminal background", and 9 more. Scans both decision text and context free-text fields.

Disparate Impact (EEOC 4/5ths)

Batch decision sets are analyzed for group-level pass rates. A protected group with a pass rate below 80% of the highest group's rate triggers an EEOC disparate impact flag automatically.

State Law Overlays

California FEHA, New York HRL, and Illinois HRA add state-level protected classes and stricter thresholds on top of federal (ECOA/EEOC) baseline. Applied based on geographic scope of the AI system.

Dynamic Rule Engine

Rules stored in compliance_rules table. Default action (FAIL/FLAG/ALLOW) and threshold are configurable per org via org_rule_overrides. Changes take effect immediately — no deployment required. Full audit trail of who changed what.

Python SDK

Separate installable package that wraps OpenAI-compatible clients with one line of code.

Integration

from openai import OpenAI
from pragma import Pragma, ComplianceError

client = Pragma(
    OpenAI(),
    policy_id="hr-compliance-v1",
    pragma_api_key="pragma_...",
    mode="block",          # block | flag | audit
    block_threshold=0.8,   # tune sensitivity
)

try:
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role":"user",
          "content":"Reject her — she is 58."}]
    )
except ComplianceError as e:
    print(e.result.firewall_action)  # "block"
    print(e.result.risk_flags)       # ["bias","discrimination"]
    print(e.result.violations[0].regulation)

Architecture

  • Pragma() / AsyncPragma() — factory functions returning wrapped client
  • Intercepts chat.completions.create() — same interface as underlying client
  • Calls POST /evaluate-decision on the Pragma backend before forwarding to OpenAI
  • Mode block — raises ComplianceError with full ComplianceResult
  • Mode flag — passes through, attaches .pragma_result to response
  • Mode audit — passes through silently, violations logged server-side
  • Supports sync + async, OpenAI + AzureOpenAI
  • Configurable block_threshold per client instance

Data & Privacy

No personal data stored. Feedback drives model improvement, not user profiling.

What We Store

  • Anonymous session ID (SHA-256 hash, not reversible)
  • Request timestamp
  • Context field names only (not values)
  • Decision word count (not the text)
  • Provider used (pragma / claude / openai / mock)
  • Confidence score, risk flag count, decision category
  • Feedback ratings (👍 / 👎) per category — for model retraining
  • Audit log: sha256 input hash, firewall verdict, proxy vars detected, HITL override reason
  • AI system profiles (company name, risk tier, training data sources) — EU AI Act Art. 10
  • Compliance certificates (certificate ID, articles status, issue date)
  • User email (Google-authenticated users only) — for compliance notifications
  • Notification log — deduplication of sent welcome/gap/countdown emails
  • Daily compliance score snapshots per system — powers Dashboard trend charts

What We Never Store

  • User email or name
  • Google account details
  • The actual decision text
  • Context field values
  • IP addresses
  • Any personally identifiable information

L1 Compliance Engine

Deterministic rule evaluation: HOLC historically redlined zip codes (500+ across 35 US cities), ECOA proxy variables (35+ fields), indirect phrasing (14 categories), compound risk detection, state law overlays (CA/NY/IL). DB-backed rules with per-org overrides — no redeploy needed.

L2 — Claude (Anthropic)

claude-sonnet-4-6 primary. Streams regulatory reasoning across EU AI Act, ECOA, EEOC, FCRA, CFPB. Also powers evidence analyzer (document upload validation) and guided interview scoring.

Outputs

  • Firewall verdict: BLOCK / FLAG / ALLOW
  • Regulatory refs + risk flags (JSON)
  • ECOA §1002.9 adverse action notice
  • FCRA §615(a) consumer disclosure
  • EEOC 4/5ths disparate impact report
  • W3C PROV JSON-LD audit export
  • PDF compliance certificate

Security Hardening

Controls applied across the stack as of Q2 2026.

XSS Prevention

esc() helper using document.createTextNode() applied to every dynamic HTML injection site in the frontend — system name, company, article evidence, risk flags, counterfactual keys, wizard review rows. No raw innerHTML from server data.

CORS Hardening

Explicit origin allowlist via ALLOWED_ORIGINS env var replaces the previous allow_origins=["*"]. Wildcard origins allow any site to make authenticated API calls from a logged-in user's browser — the allowlist prevents this.

Input Limits

Decision text capped at 4,000 characters. Context payload capped at 8,000 characters. Both enforced at the FastAPI layer with HTTP 400 before the LLM is called — prevents prompt injection via oversized inputs.

Batch Rate Limiting

The /evaluate-batch endpoint now checks the monthly plan limit before processing any rows. Previously, free users could bypass the 100 eval/month limit by uploading a 100-row CSV in a single batch call.

SQL Injection Guard

Column names in the ALTER TABLE migration path are validated against re.compile(r'^[a-z_][a-z0-9_]*$') before being interpolated into SQL. Unknown column names are logged and skipped rather than executed.

Stripe Webhook Auth

Webhook payloads are verified with stripe.WebhookSignature.verify_header() using the signing secret before any database writes occur. Unsigned or tampered events return HTTP 400 immediately.
